# واحة القرآن — Quran Oasis

> كل يوم خطوة أقرب إلى القرآن.

منصة ويب عربية (RTL) تساعد المستخدم على قراءة القرآن الكريم، والمحافظة على الأذكار، وبناء ورد يومي، والحفظ والمراجعة، والتعلّم والتدبّر — في تجربة هادئة تعمل على الهاتف أولًا، وتعمل كاملةً دون حساب، ويمكن تثبيتها كتطبيق (PWA) والقراءة دون اتصال.

## التقنيات والبنية

- **Next.js 16** (App Router، Turbopack) + **React 19** + **TypeScript**
- **Tailwind CSS 4**، خطوط Cairo (واجهة) و Amiri Quran (المصحف) و Amiri (الأذكار) مستضافة ذاتيًا عبر `next/font`
- **Supabase** (Postgres + Auth) عبر `@supabase/ssr` — اختياري؛ بدونه تعمل المنصة بوضع الزائر
- **PWA**: `manifest.webmanifest` و Service Worker مكتوب يدويًا (`public/sw.js`)
- اختبارات: **Vitest** (وحدات وتكامل) و **Playwright** (طرفية) و SQL (سياسات RLS)

```
quran-oasis/
├── public/data/quran/{1..114}.json   نص القرآن المعتمد (مولّد ومُتحقق منه)
├── public/sw.js                      Service Worker
├── scripts/                          بناء بيانات القرآن والتحقق منها، توليد seed.sql، تشغيل اختبارات القاعدة
├── supabase/migrations/              المخطط وسياسات RLS والدوال
├── supabase/seed.sql                 المحتوى الافتتاحي (مولّد)
├── supabase/tests/                   اختبارات الصلاحيات
├── src/app/(site)/                   الصفحات العامة (الرئيسية، القانونية)
├── src/app/(app)/                    صفحات التطبيق ولوحة الإدارة
├── src/content/                      المحتوى الافتتاحي (أذكار، لحظات، دروس، مصادر)
├── src/lib/quran/                    بيانات القرآن وطبقة المصدر القابلة للاستبدال
├── src/lib/store/                    حالة المستخدم المحلية + المزامنة + حسابات التقدم
├── src/lib/supabase/                 عملاء Supabase للمتصفح والخادم
├── src/proxy.ts                      تحديث الجلسة وحماية /admin
├── tests/unit, tests/integration     اختبارات Vitest
└── e2e/                              اختبارات Playwright
```

**الحفظ المحلي (يعمل دون أي خادم):**
1. `localStorage` — النسخة الأساسية السريعة.
2. **IndexedDB** — نسخة مرآة تُحدَّث تلقائيًا؛ إن مُسح `localStorage` أو تلف تُستعاد البيانات منها عند الفتح التالي (مُختبر آليًا).
3. **لقطات يومية تلقائية** لآخر ٧ أيام يمكن الرجوع إليها من الإعدادات.
4. طلب **«تخزين دائم»** من المتصفح (`navigator.storage.persist`) حتى لا يحذف البيانات عند امتلاء الجهاز.
5. **تصدير واستيراد** نسخة احتياطية JSON (دمج أو استبدال) مع التحقق من الملف.
6. إعدادات الجهاز (الموقع، طريقة الحساب) في مفتاح منفصل **لا يُزامن أبدًا**، والموقع يُقرّب إلى نحو ١ كم.
7. عند تسجيل الخروج أو «مسح البيانات» تُحذف النسخ المحلية كلها حتى لا تُستعاد على جهاز مشترك.

**حالة المستخدم:** مخزن محلي واحد (`src/lib/store`) يعمل للجميع، وعند تسجيل الدخول تُزامن كل شريحة (الإعدادات، الموضع، المفضلة، سجل القراءة، الأذكار، المهام، الختمات، الحفظ، الدروس، الخواطر) كوثيقة في جدول `user_documents`. الدمج حتمي وتبادلي (السجل الأحدث يفوز، وسجل القراءة يُوحَّد)، فلا تضيع بيانات بين الأجهزة، ويستمر العمل دون اتصال ثم يُزامن لاحقًا.

**المحتوى العام** (أذكار، لحظات، دروس) يُقرأ من قاعدة البيانات إن كانت Supabase مهيأة (ويديره فريق المحتوى من لوحة الإدارة)، وإلا من المحتوى المضمّن في `src/content`.

**الذكاء الاصطناعي:** غير مُدمج في هذه النسخة عمدًا. البنية تفصل المحتوى المعتمد (جداول بمصادر) عن العرض، ما يسمح لاحقًا بمساعد يسترجع من هذه القاعدة فقط ويعرض المصادر.

## مصدر النص القرآني والتحقق منه

- **النص:** مصحف المدينة النبوية برواية حفص عن عاصم — **مجمع الملك فهد لطباعة المصحف الشريف** (النص العثماني، الإصدار 13)، كما ينشره مستودع `fawazahmed0/quran-api` (edition: `ara-quranuthmanihaf`). يُعرض **حرفيًا دون أي تعديل**.
- **تحقق مستقل:** يقارن `scripts/build-quran-data.mjs` الهيكل الحرفي لكل آية (الحروف بعد إزالة علامات الضبط) مع نص **موسوعة القرآن الكريم QuranEnc** (حزمة `quran-json`، CC BY 4.0) — **تطابق 6236 آية من 6236**، ويتحقق من أعداد الآيات لكل سورة مقابل `quran-meta`. الفروق بين المصدرين في **ترميز** علامات الضبط فقط (مثل التنوين المفتوح U+08F0–08F2)، لا في الحروف.
- **بيانات المصحف الوصفية:** صفحات مصحف المدينة (604)، الأجزاء، الأحزاب، السجدات من `quran-meta` (MIT).
- **بصمة النص:** `6ab953568061c085670a8595e69feab6fc9675d75a8488bff589a39d6fd96d19` (SHA-256)، يتحقق منها `npm run data:verify` واختبارات الوحدات.
- **لا يُكتب أي نص قرآني يدويًا:** الأذكار القرآنية والدروس ولحظة واحة تخزّن **مراجع** (سورة/آيات)، ويُعرض النص من الملف المعتمد. اختبار آلي يتأكد من عدم وجود نص بالرسم العثماني داخل نصوص الأذكار والدروس.
- **طبقة مستقلة:** `src/lib/quran/source.ts` تعرّف واجهة `QuranTextSource`؛ يمكن تبديل المصدر (مثل API رسمي) دون تعديل الواجهات. عند تعذّر التحميل تُعرض رسالة واضحة، ولا يُعرض أي نص بديل.
- لإعادة بناء البيانات: `npm run data:build` (يتطلب اتصالًا، ويرفض أي تغيير في المصدر ما لم تُحدَّث البصمة بعد مراجعة يدوية).

> **ترخيص:** يُسمح عمومًا بنشر نص مجمع الملك فهد دون تعديل مع نسبته. يُنصح بمراجعة شروط المجمع الرسمية قبل الإطلاق التجاري. معاني «لحظة واحة» مقتبسة باختصار من **التفسير الميسر** (مجمع الملك فهد) مع ذكر المصدر؛ لم يُدرج التفسير كاملًا في المنصة لحين التأكد من شروط إعادة نشره.

## التشغيل المحلي

المتطلبات: Node.js 20.9+ (المُختبر: 22).

```bash
cd quran-oasis
npm install          # ملف .npmrc يضبط legacy-peer-deps بسبب تعارض نسخ peer في vitest
npm run dev          # http://localhost:3000
```

بدون أي متغيرات بيئة تعمل المنصة كاملة بوضع الزائر. لاختبار سلوك الإنتاج (Service Worker والعمل دون اتصال):

```bash
npm run build && npm start
```

## متغيرات البيئة

انسخ `.env.example` إلى `.env.local`:

| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | للحسابات | رابط مشروع Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | للحسابات | المفتاح **العام** (anon / publishable). آمن للواجهة لأن الحماية عبر RLS |
| `NEXT_PUBLIC_SITE_URL` | للإنتاج | مثل `https://quranoasis.com` (لـ SEO والروابط) |

**لا تحتاج المنصة مفتاح `service_role` إطلاقًا.** لا تضعه في أي متغير، ولا ترفع ملفات `.env*` (مستثناة في `.gitignore`).

## إعداد Supabase

1. أنشئ مشروعًا جديدًا في [Supabase](https://supabase.com) (يُفضّل مشروعًا مستقلًا لهذه المنصة).
2. **المخطط:** افتح SQL Editor ونفّذ محتوى `supabase/migrations/20261016000000_init.sql`، ثم `supabase/seed.sql` لإدراج المحتوى الافتتاحي.
   أو عبر Supabase CLI:
   ```bash
   supabase link --project-ref <ref>
   supabase db push
   psql "<connection-string>" -f supabase/seed.sql
   ```
3. **المصادقة** (Authentication → URL Configuration):
   - Site URL: `https://<نطاقك>`
   - Redirect URLs: `https://<نطاقك>/auth/callback` و `http://localhost:3000/auth/callback`
   - فعّل Email provider وتأكيد البريد (Confirm email).
   - يُنصح بإعداد SMTP خاص (Auth → SMTP) لأن البريد الافتراضي محدود العدد.
   - اختياري: عرّب قوالب البريد (Auth → Email Templates).
4. ضع `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY` في `.env.local` أو في Vercel.

**ما يحميه المخطط** (مُختبر في `supabase/tests/10_rls_test.sql` وفي اختبارات التكامل):
- RLS على كل الجداول؛ كل مستخدم يقرأ ويكتب وثائقه فقط.
- لا يستطيع أي مستخدم تغيير دوره (trigger يرفض ذلك حتى عبر API مباشرة)، ولا يمكن إزالة آخر مدير.
- المدير **لا يقرأ** تقدم المستخدمين أو خواطرهم؛ يرى إحصاءات مجمّعة فقط.
- المحتوى العام يُقرأ منشورًا فقط (المسودات واللحظات المجدولة مستقبلًا مخفية)، والكتابة للطاقم (`editor`/`admin`).
- المعنى في لحظة واحة لا يُقبل بلا مصدر (قيد في القاعدة).
- `delete_my_account()` يحذف الحساب وكل بياناته (cascade).

## إنشاء حساب المدير

لا توجد كلمة مرور أو حساب إداري ثابت في الكود. الطريقة الآمنة:

1. سجّل حسابًا عاديًا من `/signup` وأكّد البريد.
2. في Supabase → SQL Editor نفّذ:
   ```sql
   select public.promote_to_admin('you@example.com');
   ```
   هذه الدالة غير متاحة عبر API (مسحوبة الصلاحية من anon و authenticated)، فلا تُنفّذ إلا من لوحة Supabase.
3. أعد تحميل المنصة؛ سيظهر رابط «لوحة الإدارة». يمكنك بعدها منح دور «محرر محتوى» أو «مدير» لغيرك من `/admin/users`.

## النشر على Vercel والنطاق

1. استورد المستودع في Vercel، واضبط **Root Directory** على `quran-oasis`.
2. Framework: Next.js (يُكتشف تلقائيًا). Install: `npm install`. Build: `npm run build`.
3. أضف متغيرات البيئة أعلاه (Production و Preview).
4. **النطاق** (بعد التأكد من توفره وحجزه — لم نفترض أن `quranoasis.com` متاح):
   - في Vercel → Domains أضف `quranoasis.com` و `www.quranoasis.com`.
   - عند مسجّل النطاق: سجل `A` للنطاق الجذر يشير إلى `76.76.21.21`، وسجل `CNAME` لـ `www` يشير إلى `cname.vercel-dns.com` (أو اتبع القيم التي يعرضها Vercel).
   - حدّث `NEXT_PUBLIC_SITE_URL` وإعدادات Site URL/Redirect URLs في Supabase إلى النطاق النهائي.
5. التكلفة: يمكن البدء بالخطط المجانية لـ Vercel و Supabase.

**اختُبر فعليًا (آليًا):**
- البناء الإنتاجي (163 صفحة مولّدة مسبقًا، منها 114 سورة)، TypeScript، ESLint.
- 30 اختبار وحدات (منها مواقيت مكة المطابقة لتقويم أم القرى، والقبلة، والنسخ الاحتياطية): سلامة بيانات القرآن (العدد والترتيب والبصمة)، الصفحات والأجزاء، البحث والانتقال، حسابات الهدف والختمة والسلسلة، قواعد الدمج والمزامنة، صحة المحتوى ومراجعه، منع إعادة التوجيه المفتوحة.
- 25 اختبارًا طرفيًا في Chromium (منها: الإعداد الأولي، مواقيت مدينة مختارة، المسبحة، الاستعادة التلقائية من IndexedDB بعد مسح localStorage، التصدير والاستيراد) (Pixel 7 وحاسوب 1366px): الصفحة الرئيسية، البحث والانتقال لآية، حفظ الموضع واستعادته، احتساب القراءة، البسملة (الفاتحة/التوبة)، المفضلة والعلامة والنسخ مع النسبة، عدّاد الأذكار وحفظه وإعادة ضبطه، الخطة والمهام والختمة والتسجيل اليدوي، الحفظ والمراجعة، لحظة واحة والخاطرة، الدروس، الإعدادات والوضع الداكن والتصدير، التنقل بالهاتف والحاسوب ولوحة المفاتيح، عدم وجود تمرير أفقي أو أخطاء JavaScript، **تنزيل المصحف ثم القراءة بعد إيقاف الخادم كليًا** وظهور صفحة «غير متصل» للصفحات غير المخزنة.
- سياسات RLS والدوال على Postgres 16 محلي ببيئة auth محاكية.
- تكامل حقيقي: supabase-js → PostgREST 12 → Postgres: نقل بيانات الزائر، رفع التعديلات، تسجيل الخروج والاستعادة، عزل المستخدمين، رفض رفع الدور، قراءة الزائر للمحتوى، الدوال الإدارية، حذف الحساب.

**لم يُختبر (يحتاج إعدادًا خارجيًا):**
- خدمة Supabase Auth الحقيقية: التسجيل وتأكيد البريد واستعادة كلمة المرور ورابط `/auth/callback` (لا يوجد مشروع Supabase مخصص لهذه المنصة بعد). منطق الصلاحيات نفسه مُختبر، أما تدفقات البريد فتحتاج مشروعًا فعليًا.
- لوحة الإدارة بواجهتها في المتصفح مع مستخدم حقيقي (العمليات التي تعتمد عليها مُختبرة على مستوى القاعدة وAPI).
- أجهزة حقيقية (iOS Safari / Android) وتثبيت PWA عليها؛ الاختبار تم على Chromium بمحاكاة الهاتف.
- قارئات الشاشة يدويًا (اعتُمدت تسميات ARIA والأدوار ولوحة المفاتيح).

## قرارات وملاحظات مهمة

- **مراجعة شرعية مطلوبة قبل الإطلاق العام:** الأذكار (64 ذكرًا) مختارة من صحيح الأذكار المشهورة مع تخريجها بأرقام الأحاديث كما في كتب الأذكار المعتمدة، والدروس تمهيدية مستندة إلى المتون المشهورة. يجب أن يراجعها مختص؛ وفي لوحة الإدارة حقل «تمت مراجعته شرعيًا» لكل ذكر (القيمة الافتراضية: لا).
- **التأملات** في لحظة واحة تحريرية وموسومة بذلك صراحة، ومنفصلة عن النص القرآني والمعنى المنقول.
- **التاريخ الهجري** من تقويم أم القرى المدمج في المتصفح، ويُخفى إن لم يدعمه المتصفح؛ قد يختلف بيوم عن الرؤية المحلية.
- **التذكيرات** داخل التطبيق فقط وبعد تفعيل صريح من المستخدم، وتظهر أثناء فتح المنصة؛ لا توجد إشعارات Push من خادم في هذه النسخة.
- **احتساب القراءة:** تُحتسب الآية بعد بقائها ظاهرة زمنًا يتناسب مع طولها، ويمكن التسجيل اليدوي أو «قرأت حتى هنا». الصفحة = مجموع نسب آيات الصفحة في مصحف المدينة.
- **الحفظ** أداة تنظيمية فقط؛ لا يوجد تحقق صوتي من التلاوة.
- **التلاوة الصوتية** غير مُضمّنة: لم نتمكن من التحقق من مصدر صوتي مرخص وروابط ثابتة من بيئة التطوير، وفضّلنا عدم إضافة روابط غير موثقة (P2).
- لا إعلانات، ولا تتبع تحليلي من طرف ثالث.
