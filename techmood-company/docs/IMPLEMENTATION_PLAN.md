# خطة التنفيذ — الموقع الرسمي لـ TechMood Technology

## 1. فحص المستودع (ما وُجد)
- `IbrahemJBadawi/IbrahemJBadawi` مستودع الملف الشخصي، ويضم مشاريع مستقلة: `halaqati/` (منصة حلقتي، Next.js 16 + Supabase)، و`jamal-platform/` (متجر الجمال، Next.js 16)، و`techmood-exports/` (تصدير محتوى الأكاديمية).
- منصة TechMood نفسها في مستودع منفصل `IbrahemJBadawi/techmoodtech` (Next.js 16 + Supabase)، ومنها أُخذ **الشعار الأصلي** وروابط الحسابات الرسمية. لم يُعدَّل ذلك المستودع.
- لا يوجد موقع للشركة الأم. لذلك أُنشئ تطبيق مستقل في `techmood-company/` بنفس تقنيات المشاريع الشقيقة، دون المساس بالمنصة أو بحلقتي أو بالجمال.

## 2. القرارات
| القرار | السبب |
|---|---|
| مجلد مستقل `techmood-company/` | المستودع يجمع مشاريع مستقلة؛ لا يُحوَّل أي منها. يمكن نقله لاحقًا إلى مستودع خاص دون تغيير (انظر DEPLOYMENT.md). |
| Next.js 16 + TypeScript + CSS بالـ tokens | نفس إطار المشاريع الأخرى؛ بلا مكتبات واجهة ثقيلة. |
| العربية في الجذر `/` والإنجليزية في `/en` | العربية افتراضية، وعنوان واحد لكل صفحة لكل لغة (hreflang). |
| البيانات في `src/data/*` | تعديل المشاريع والخدمات من ملف واحد، دون لمس الواجهة. |
| بلا قاعدة بيانات ولا لوحة إدارة | لا حاجة فعلية لها الآن؛ التعديل عبر GitHub أبسط وأكثر أمانًا من لوحة غير محمية. |
| الحالات حسب الأدلة | منصة TechMood وحلقتي «تجريبي» (منشورتان)، الجمال «قيد التطوير» (كود بلا نشر)، Growth وواحة القرآن «مرحلة التخطيط» (لا كود). |
| نموذج التواصل لا يدّعي النجاح | يرسل عبر Resend و/أو Telegram إن ضُبطا، وإلا يقول بوضوح إنه لم يُرسل ويعرض البريد/Telegram مع حفظ المسودة. |
| ميزات منصات TechMood المناسبة | تثبيت كتطبيق (PWA)، صفحات تعمل دون اتصال، إشعارات الجهاز للمستجدات ولتغيّر حالة المشاريع المتابَعة، وضع داكن — وكلها بالتخزين المحلي، بلا خادم ولا تتبع. |

## 4. ما يحتاج المالك
- تحديد النطاق النهائي ووضعه في `NEXT_PUBLIC_SITE_URL` (حتى ذلك الحين الموقع لا يُفهرس).

- إنشاء مشروع Vercel بجذر `techmood-company`.
