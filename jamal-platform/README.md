# منصة الجمال — JAMAL

متجر أزياء عربي (RTL) بنموذج **دروبشيبينغ يدوي**: المنتجات مرتبطة بموردين، والطلبات تُسجّل في المتجر ثم تُرسل للمورد يدويًا من لوحة الإدارة. لا يوجد دفع إلكتروني ولا تكامل آلي مع الموردين في هذا الإصدار.

- **التقنيات:** Next.js 16 (App Router، Cache Components)، TypeScript، Tailwind CSS 4، PostgreSQL مع سياسات RLS متوافقة مع Supabase، Zod، lucide-react.
- **قاعدة البيانات:** PGlite (Postgres مدمج، بدون أي إعداد) للتطوير، أو أي Postgres عبر `DATABASE_URL` (Supabase في الإنتاج).
- **المصادقة:** محلية (bcrypt + كوكي موقّع httpOnly) أو Supabase Auth.

## التشغيل محليًا (بدون أي حسابات خارجية)

المتطلبات: Node.js 20.9 أو أحدث.

```bash
cd jamal-platform
npm install
npm run setup        # ينشئ .env.local ويولّد AUTH_SECRET عشوائيًا
npm run db:migrate   # ينشئ قاعدة PGlite في .data/pglite ويطبق الـ migrations
npm run seed:demo    # (اختياري) كتالوج تجريبي واضح العلامة للاختبار
npm run dev          # http://localhost:3000
```

### إنشاء أول مسؤول (Admin)
1. سجّل حسابًا من صفحة `/register`.
2. **أوقف** `npm run dev` (قاعدة PGlite تُفتح من عملية واحدة فقط)، ثم:
   ```bash
   npm run admin:grant -- your@email.com
   ```
3. شغّل `npm run dev` مجددًا وافتح `/admin`.

> مع Postgres حقيقي (`DATABASE_URL`) لا حاجة لإيقاف الخادم.

### البيانات التجريبية
`npm run seed:demo` يضيف 14 منتجًا تجريبيًا (رسومات خطية أصلية، بلا صور ماركات)، ومورّدًا تجريبيًا، ومنطقتي شحن تجريبيتين (الأردن والسعودية بالدولار). كل ذلك موسوم بوضوح:
- شارة «منتج تجريبي» وشريط تنبيه في كامل المتجر.
- الطلبات التي تحتوي منتجات تجريبية تُسجّل **كطلبات اختبار** وتُستثنى من المبيعات والأرباح.
- للحذف الكامل قبل الإطلاق: `npm run seed:demo -- --remove`.

|---|---|
| `npm run dev` | خادم التطوير |

| `npm run test:e2e` | اختبارات شاملة بالمتصفح (تتطلب `DATABASE_URL` لـ Postgres + `npm run build`) |

| `npm run seed:demo [-- --remove]` | إضافة/حذف البيانات التجريبية |

لتشغيل اختبارات المتصفح محليًا مع Postgres:
```bash
export DATABASE_URL=postgres://user:pass@localhost:5432/jamal
npm run db:migrate && npm run seed:demo && npm run build && npm run test:e2e
```

## الإعداد على Supabase (خطوة بخطوة)

الخطة المجانية لـ Supabase كافية للبداية (مشروعان نشطان، 500MB قاعدة بيانات، 1GB تخزين؛ المشاريع الخاملة قد تتوقف مؤقتًا بعد أسبوع دون نشاط في الخطة المجانية).

1. **أنشئ مشروعًا** على [supabase.com](https://supabase.com) (اختر منطقة قريبة، مثل Frankfurt `eu-central-1`). احفظ كلمة مرور قاعدة البيانات في مدير كلمات مرور، لا في الكود.
2. **طبّق المخطط:** إما
   - بـ Supabase CLI: `supabase link --project-ref <ref>` ثم `supabase db push` (يقرأ `supabase/migrations/`)،
   - أو انسخ محتوى ملفات `supabase/migrations/*.sql` بالترتيب إلى **SQL Editor** وشغّلها.
   > لا تطبّق `db/local/auth_shim.sql` على Supabase؛ فهو للتطوير المحلي فقط.
3. **اجلب القيم** من *Project Settings*:
   - `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` (المفتاح العام/publishable) — من *API*.
   - `DATABASE_URL` — من زر *Connect* ← **Transaction pooler** (المنفذ 6543). **سري، للخادم فقط.**
   - `SUPABASE_SERVICE_ROLE_KEY` — فقط إن أردت رفع الصور إلى Supabase Storage. **سري جدًا، للخادم فقط، ولا يبدأ أبدًا بـ `NEXT_PUBLIC_`.**
4. **المصادقة:** في `.env.local` (أو إعدادات Vercel) اضبط `AUTH_PROVIDER=supabase`. في *Authentication → URL Configuration* أضف رابط موقعك. يُنصح بإبقاء تأكيد البريد مفعّلًا.
5. **الصور (اختياري):** أنشئ حاوية Storage باسم `product-images` واجعلها **Public**، ثم ضع `SUPABASE_SERVICE_ROLE_KEY`.
6. **أول مسؤول:** سجّل من الموقع، ثم شغّل محليًا مع `DATABASE_URL` الخاص بـ Supabase:
   `npm run admin:grant -- your@email.com` — أو في SQL Editor:
   `update public.profiles set role = 'admin' where email = 'your@email.com';`

## النشر على Vercel

الخطة المجانية (Hobby) مناسبة للتجربة؛ للاستخدام التجاري تشترط Vercel خطة Pro (حاليًا نحو 20$ شهريًا لكل عضو) — تحقق من الأسعار الحالية قبل الإطلاق التجاري.

1. استورد المستودع في Vercel واجعل **Root Directory** = `jamal-platform`.
2. أضف متغيرات البيئة: `NEXT_PUBLIC_SITE_URL`، `DATABASE_URL`، `AUTH_PROVIDER=supabase`، `NEXT_PUBLIC_SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_ANON_KEY`، و(اختياريًا) `SUPABASE_SERVICE_ROLE_KEY`، `SUPABASE_STORAGE_BUCKET`.
3. انشر. **لا تستخدم PGlite ولا التخزين المحلي للصور على Vercel** (لا يوجد قرص دائم).
4. الصور تُعرض دون خدمة تحسين الصور المدفوعة (`images.unoptimized`) لتجنب حصص الاستهلاك.

## البنية

```
jamal-platform/
├─ supabase/migrations/   مخطط القاعدة + RLS + البيانات المرجعية (دول، عملات، فئات، صفحات)
├─ db/local/auth_shim.sql محاكاة auth.users و auth.uid() للتطوير المحلي فقط
├─ scripts/               migrate, seed-demo, grant-admin, setup
├─ src/app/(store)/       واجهة المتجر
├─ src/app/admin/         لوحة الإدارة
├─ src/lib/db/            طبقة الاتصال (PGlite / postgres.js) وسياقات الأمان
├─ src/lib/auth/          محوّلا المصادقة (local / supabase)
├─ src/lib/orders/        التسعير وإنشاء الطلبات على الخادم
├─ src/lib/pricing.ts     قواعد التسعير والشحن والدفع عند الاستلام (مغطاة باختبارات)
├─ src/lib/i18n/ar.ts     قاموس الواجهة (جاهز لإضافة en.ts)
├─ public/brand/          شعار J (قابل للاستبدال)
└─ tests/                 unit (Vitest) و e2e (Playwright)
```

### نموذج الأمان
- كل استعلام يمر بأحد ثلاثة سياقات: **anon** (زائر)، **authenticated** (عميل/مسؤول — بدور Postgres حقيقي و`auth.uid()`)، أو **system** (عمليات خادم موثوقة مثل إنشاء الطلب).
- طلبات العملاء والإدارة تمر عبر **RLS**؛ صلاحية الإدارة تُفحص في الخادم (`requireAdmin`) **وفي القاعدة** (`is_admin()`).
- العميل لا يملك صلاحية إنشاء/تعديل الطلبات أو الأسعار أو حالة الدفع؛ الأسعار والشحن والمجاميع تُحسب على الخادم فقط.
- تكاليف الموردين وسجلات التنفيذ في جداول للإدارة فقط؛ العميل يرى رقم التتبع عبر دالة `order_shipments` التي لا تعيد أي تكلفة.
- لا تغيير لدور المستخدم إلا عبر `admin_set_role` (للمسؤول فقط، ولا يمكنه خفض صلاحيته).
- سجل عمليات إداري غير قابل للتعديل أو الحذف (`audit_log`).
- حماية من التكرار المفرط (rate limit) لتسجيل الدخول والطلبات والتواصل والتتبع — داخل ذاكرة الخادم (انظر القيود).
- رفع الصور يتحقق من نوع الملف ببصمته الفعلية وحجمه (≤ 5MB).
- لا توجد أسرار في الكود؛ `.env*` مستثناة من Git عدا `.env.example`.

### العملات والشحن
- لكل منتج عملة واحدة. **لا يوجد أي تحويل عملات.** السلة لا تقبل عملات مختلفة في طلب واحد.
- منطقة الشحن = دولة + عملة + تكلفة + مدة تقديرية + هل الدفع عند الاستلام مؤكد.
- **الدفع عند الاستلام** لا يظهر إلا إذا: فعّله المتجر + منطقة الشحن تدعمه + كل مورد في السلة أكده لتلك الدولة.
- **الطلب اليدوي**: يتواصل المتجر مع العميل لتأكيد الطلب والدفع.

## ما تم إنجازه

**واجهة المتجر:** الرئيسية، جميع المنتجات، صفحات الفئات، العروض، تفاصيل المنتج (معرض صور، ألوان ومقاسات، توفر لكل خيار، مدة التوصيل حسب الدولة، سياسة الإرجاع الخاصة)، البحث (مع توحيد الحروف العربية أ/ا، ة/ه، ى/ي وتجاهل التشكيل)، فلاتر المقاس واللون والسعر والتخفيض، الترتيب، الترقيم، المفضلة، السلة، إتمام الطلب (كضيف أو بحساب)، صفحة تأكيد، تسجيل الدخول وإنشاء الحساب، الحساب، طلباتي مع مراحل الطلب ورقم التتبع، إلغاء الطلب قبل تأكيده، طلب إرجاع بعد التسليم، تتبع الطلب للضيوف (رقم الطلب + الهاتف)، اتصل بنا (يُحفظ في لوحة الإدارة)، الأسئلة الشائعة، سياسات الشحن والإرجاع والخصوصية والشروط. تصميم Mobile-first مع شريط تنقل سفلي، RTL كامل، حالات تحميل وفراغ وأخطاء، SEO (عناوين، وصف، canonical، Open Graph، JSON-LD للمنتجات، sitemap، robots).

**لوحة الإدارة:** الملخص (طلبات حسب الحالة، مبيعات لكل عملة، ربح فعلي، تنبيهات)، المنتجات (إنشاء/تعديل/حذف، رفع صور، خيارات، ربط موردين وتكاليف، هامش متوقع)، الفئات، العروض والأسعار، الموردون، الطلبات (تغيير الحالة بتسلسل منضبط، حالة الدفع، ملاحظات داخلية/مرئية، سجلات تنفيذ لكل مورد، **زر نسخ تفاصيل الطلب للمورد**، رقم التتبع، التكاليف الفعلية، الربح المتوقع والفعلي)، المرتجعات والاسترداد، العملاء والصلاحيات، الدول والعملات ومناطق الشحن، الصفحات والسياسات، رسائل التواصل، الإعدادات، سجل العمليات.

**الاختبارات:** 25 اختبار وحدة/أمان (تسعير، عملات، دفع عند الاستلام، سياسات RLS)، و7 سيناريوهات متصفح على الهاتف (تصفح، بحث، طلب كامل، تتبع، حساب ومفضلة، منع غير المسؤول من الإدارة، إدارة الطلب ووصول رقم التتبع للعميل، نموذج التواصل)، وفحص عدم وجود تمرير أفقي على شاشة الهاتف لكل الصفحات.

## ما لم يُنجز بعد (بصدق)

- **الدفع الإلكتروني:** غير موجود عمدًا. يتطلب اختيار مزود (مثل Tap أو PayTabs أو Checkout.com أو Stripe حسب الدول) وحسابًا تجاريًا واختبارًا.
- **التكامل الآلي مع الموردين:** الإرسال يدوي (نسخ ولصق). لا API موردين.
- **الواجهة الإنجليزية:** البنية جاهزة (`name_en`، قاموس `ar.ts`) لكن لا توجد صفحات إنجليزية بعد.
- **الإشعارات:** لا رسائل بريد/SMS/واتساب تلقائية للعميل أو المسؤول (تحتاج مزودًا مثل Resend — خطة مجانية محدودة).
- **الكوبونات والخصومات على مستوى السلة:** غير مدعومة (العروض حاليًا بسعر تخفيض لكل منتج).
- **استعادة كلمة المرور** في الوضع المحلي غير متوفرة (متوفرة عبر Supabase Auth عند تفعيله من لوحة Supabase، لكن صفحتها في المتجر لم تُبنَ بعد).
- **Rate limiting** في الذاكرة فقط؛ على Vercel كل نسخة لها ذاكرتها. للحماية الأقوى: Upstash Redis (خطة مجانية).
- **التخزين المؤقت (caching)** للكتالوج غير مفعّل بعد؛ كل الصفحات تُقرأ من القاعدة لكل طلب (مناسب للبداية).
- **نصوص السياسات** مبدئية وتحتاج مراجعة قانونية ومطابقة شروط الموردين وشركات الشحن.
- **لم يتم النشر** على Vercel ولم يُنشأ مشروع Supabase — بانتظار موافقتك وحساباتك.
- حالة HTTP لصفحات «غير موجود» داخل المحتوى المتدفق (streaming) تكون 200 مع وسم `noindex`، رغم ظهور صفحة 404 للمستخدم.
