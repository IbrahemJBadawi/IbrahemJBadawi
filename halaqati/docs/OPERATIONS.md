# دليل الإدارة والتشغيل

## مهام مدير المنصة
- **المستخدمون والأدوار** (`/dashboard/admin/users`): بحث، ومنح الأدوار وسحبها. لا يمكن سحب آخر مدير للمنصة.
- **التوثيق** (`/dashboard/admin/institutions`): توثيق الدور والمراكز أو إيقافها. لا يظهر في الأدلة العامة إلا الموثّق.
- **طلبات الخصوصية** (`/dashboard/admin/privacy`): متابعة طلبات نسخ البيانات والحذف.
- **سجل التدقيق** (`/dashboard/admin/audit`): للقراءة فقط.

## حذف حساب (طلب خصوصية)
1. تحقق من هوية صاحب الطلب عبر بريده المسجّل.
2. إن كان محفّظًا مسؤولًا عن حلقات: انقل المسؤولية أو أوقف الحلقات (قاعدة البيانات تمنع حذف محفّظ مسؤول عن حلقة قائمة).
3. احذف المستخدم من Supabase: Authentication → Users → Delete user. يُحذف ملفه وأدواره وعضوياته وسجلاته كطالب تلقائيًا (cascade). أما السجلات التي أنشأها كمحفّظ لطلاب آخرين فتبقى ويُفرَّغ اسم منشئها.
4. علّم الطلب «تم التنفيذ».

## نسخة من البيانات (export)
نفّذ في SQL Editor استعلامات `profiles` و`profile_details` و`quran_progress_records` و`attendance_records` و`quran_assignments` مقيّدة بـ `user_id`/`student_id` للمستخدم، وأرسل الملف عبر قناة آمنة. (أتمتة التصدير مخطط لها في المرحلة 6.)

## الاحتفاظ بالبيانات
| البيانات | المدة |
|---|---|
| الحسابات والسجلات التعليمية | ما دام الحساب قائمًا |
| حدود المحاولات (`private.rate_limits`) | تُنظّف تلقائيًا بعد يومين |
| الإشعارات | يحذفها المستخدم، ويُقترح تنظيف ما تجاوز 12 شهرًا (مهمة مجدولة لاحقًا) |
| سجل التدقيق | لا يُحذف من التطبيق؛ يُراجع حسب السياسة القانونية |

## النسخ الاحتياطي
- الخطة المجانية في Supabase لا تتضمن نسخًا يومية قابلة للاستعادة الذاتية. أضف نسخًا دوريًا خارجيًا:
  ```bash
  pg_dump "$SUPABASE_DB_URL" --format=custom --no-owner --file=halaqati-$(date +%F).dump
  ```
  شغّله يوميًا (GitHub Actions مجدول أو cron) واحفظ النسخ مشفّرة خارج المشروع.
- الخطط المدفوعة توفر نسخًا يومية واستعادة لنقطة زمنية (PITR).
- جرّب الاستعادة دوريًا على مشروع اختبار: `pg_restore --no-owner -d <test-db-url> file.dump`.

## المراقبة
- Supabase → Advisors (Security / Performance) بعد كل migration.
- سجلات Auth لمتابعة محاولات الدخول المتكررة.
